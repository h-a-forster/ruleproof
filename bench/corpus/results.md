## Precision review

Method: `measure.py --sample 40 --seed N` draws 40 compiled rules uniformly at random from all
rules in the corpus. Each was judged by hand against the source sentence *in its file context*:
correct means the rule enforces what the sentence asks and would not fail an agent that obeyed
it (a warning-severity proxy such as "manifest changed" for "don't add dependencies" counts as
correct when it is the intended approximation).

- Seed 7 (after the first tuning rounds): **38 / 40 correct**. Wrong: "Never force-push a branch
  that is in the merge queue" (forbade all force pushes) and "Run `make gen-feature-toggles`
  after changes" (the item is about feature-toggle changes only, not every change).
- Both were then fixed (scoped force-push phrasing is skipped; bare "after changes" no longer
  counts as an obligation), and a fresh sample was reviewed.
- Seed 8: **39 / 40 correct**. Wrong: "Never use `bun test` directly" also produced a ban on
  every `bun` command (the tool-substitution recogniser read `bun test` as `bun`). Fixed
  afterwards; the run above includes the fix.

Observed precision: 77 / 80 (96%) across the two reviews, all three errors since fixed.
Coverage is low by design: most directives in these files are style and design guidance with
no deterministic check (naming, architecture, review etiquette), and the compiler only emits
rules for phrasing it understands.
